# Games I Beat

A visual log of the video games I have completed since 2024: a card per
game, yearly totals, and three views of each year - a Top 3 podium, an
hours-vs-price scatter, and hours by platform. The data lives in a private
Google Sheet and is baked into the build, so the deployed page is fully
static and makes no third-party requests.

Live at https://dcm593.github.io/game-completion-list/

## Running it

```bash
npm install
npm run dev       # dev server with live reload at http://localhost:8080
npm run build     # production bundle into dist/ (minified, no source maps)
npm run deploy    # builds, then publishes dist/ to the gh-pages branch
```

Restart the dev server after editing `webpack.config.js`.

## How it works

- **Data flow.** `npm run sync` reads the sheet and writes `games.json`.
  `parse.js` is the only code that knows how the sheet is laid out; `adapt.js`
  turns its records into the shape the views use and works out everything
  that never changes after load (per-year lists, totals, podiums, counts).
- **Rendering.** A small DOM builder (`ui/dom.js`), no framework. The header,
  year bar and rail are built once; each year section swaps only the part a
  click changes - its view, or its card grid.
- **Styling.** Everything visual is in `src/styles/`. The one exception is a
  platform's colour, which is data (`ui/theme.js`) and reaches the CSS as
  `--pc`, set inline on whatever it tints.
- **Responsive.** Below 1100px the rail gives way to a sticky year bar; below
  720px the page switches to a phone layout. The scatter is the only view
  whose geometry is computed in JS, so it redraws when the 720px breakpoint is
  crossed (`ui/media.js`).
- **Fonts.** Space Grotesk and JetBrains Mono are bundled from the
  `@fontsource-variable` packages rather than loaded from Google Fonts.

## Data sync

Game data lives in a private Google Sheet and is baked into
`src/data/games.json` at build time. The site never talks to Google, so the
deployed page is fully static and the JSON is version-controlled.

### One-time setup

1. In the Google Cloud console, enable the **Google Sheets API**.
2. Create a **service account** (IAM & Admin → Service Accounts). No roles are
   needed — access is granted by the sheet, not by IAM.
3. Add a **JSON key** to it and download the file.
4. Open the sheet → **Share** → add the service account's
   `…@….iam.gserviceaccount.com` address as a **Viewer**. This is the step that
   actually grants access; skipping it produces a 403 even though auth succeeds.
5. Point `.env` at the key (both files are git-ignored):

   ```
   GOOGLE_APPLICATION_CREDENTIALS=C:/path/to/service-account.json
   ```

   Or paste the JSON inline as `GOOGLE_SERVICE_ACCOUNT_KEY={...}`.

### Scripts

| Command | What it does |
| --- | --- |
| `npm run sync` | Reads the sheet, writes `src/data/games.json`, checks the parsed totals against the sheet's own totals row. Refuses to write if a title's colour matches no platform in the legend. |
| `npm run probe -- 18 30` | Dumps raw, unmasked cell data for the given 1-based rows, for working out how the sheet encodes something. |

## Cover art

Landscape art is fetched from SteamGridDB at build time and committed under
`src/assets/covers/`, so the deployed page makes no third-party requests.

```
npm run covers              # resolve anything not already downloaded
npm run covers -- --dry     # report resolutions without downloading
npm run covers -- --force   # re-resolve everything
```

Add `STEAMGRIDDB=<key>` to `.env`. Every resolution prints the name SteamGridDB
actually matched, prefixed with `~` when it differs from the search term, so a
bad match is visible immediately.

Rows that aren't standalone games (DLC, chapter splits, mods, challenge modes)
are corrected in `src/data/cover-overrides.js`, which maps a sheet title to a
different search term, an exact SteamGridDB id, or a hand-supplied file in
`src/assets/covers/manual/`.

### Two sizes

Every cover is stored at up to 1000px wide - 2x the podium's first-place art,
the largest place one is drawn - and again at 600px under
`src/assets/covers/small/` for the grid and the hover card. The page offers
both through `srcset`, so the browser downloads whichever is enough for the
screen. `npm run covers` cuts a small copy for any cover that lacks one or
has changed since, and writes the widths into `covers.generated.js`.

### Optimizing hand-supplied art

Hand-supplied art arrives at whatever size it was downloaded at. To cap it at
the 1000px width and convert it to WebP, run

```
npm run optimize
```

then `npm run covers` to cut the small copies and regenerate the map. The
optimizer rewrites the file references in `cover-overrides.js` if an
extension changes, and is idempotent. Originals stay in git history.

Size matters here for two reasons: transfer bytes, and decoded memory. A
browser expands every image to width x height x 4 bytes of RAM regardless of
how small it is displayed, so a 3840x1240 cover cost 18MB of memory to draw a
253px card.

### Badge images

The platinum trophy and 100% badge come from the spreadsheet's own in-cell
images. Sheets does not expose those through the REST API, but an `.xlsx`
export is a zip and they sit in `xl/media/`; `xl/drawings/drawing1.xml` maps
each one to the legend row that gives it meaning.

They arrive far larger than they are drawn, so they are downscaled with sharp:

```
node scripts/downscale-png.js <in.png> <out.png> 96
```

96px is 3x the size the badges are drawn at, so they stay sharp on any
display.
